# FMPL Super Greeble production standard — V01

A **Super Greeble pass is machine construction**, not scattering bolt meshes. Every visible addition needs a grounded process purpose, a load path to the already installed concrete pad, readable pipe/power/steam continuation, and clear value at the single canonical 45°/0° production camera.

**Super Greeble machinery roles:** exterior motor/flywheel with keyed motion; filter cartridge clamps, purge valves and supported pressure takeoffs; visible before/after sample glasses; process pressure dials and needles; armored conduit and bolted straps; glass-chamber aeration; real radiator pipes and condensate drainage. Supports must physically land on the established construction pad, and do not cross the inlet/outlet ring keep-out.

**Absolute constraints:**
- Never overwrite or retopologize the source 50 MH7 meshes, 136 process meshes, original fixed camera, or two 0.49 open-bore/0.68 flange cardinal pipe interfaces.
- Restrict added geometry to the 3×3 footprint and preserve native Factorio fluidbox review as incomplete.
- Use the committed FMPL PBR materials and real Blender mesh geometry; no fake greebles via an image generator.
- One fixed production view only: idle (frame 1) plus 8 keyed working frames (1, 13, 25, 37, 49, 61, 73, 85). Keep source textures and Blender actions editable. Produce idle + working atlases at 64, 128, 256 px.
- The 320-mesh private Greebles.blend collection is **partially appearance-classified but not approved for functional roles or redistribution**. When the exact local SHA-verified donor is available, verify provenance and create a separate private reviewed candidate; never automatically append an unclassified kitbash part into publicly uploaded GLBs or present it as a working mechanical joint.
- Standard old boiler/condenser pipe geometry is the authority for actual connecting mouths. This stage adds supplementary process fittings, *not* changes to the two canonical connectors.

**Review proof:** full-size real Blender idle-vs-active renders; one-angle production sprite, eight real working frames and animated proof if useful; manifest with source hashes, mesh count, PBR image count and independent GLB readback. Physical clearance, review/appearance, runtime pipe port and game integration remain explicit separate gates.

No extra workflows, no parallel builds, no model downloads and no automatic release.
